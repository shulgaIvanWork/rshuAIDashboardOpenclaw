## 1. Источники данных

### 1.1. Воронки (категории сделок)

В дашборде участвуют **3 воронки**:

| ID | Название | Описание |
|---:|---|:---|
| 0 | **Sale** («Общая (по умолчанию)») | Основные продажи — сюда приходят сделки на оплату |
| 8 | **Pre Sale** | Предпродажная подготовка (лиды до передачи в ОП) |
| 19 | **КОМ (Sale)** | Корпоративное обучение (B2B-проекты) |

### 1.2. Что НЕ входит

Категории, которые **исключены** из всех расчётов:
- Post Sale (категория 9) — постпродажное сопровождение
- Аккаунтинг (категория 10)
- Отказы (категория 12)
- Repeat Sale (категория 13)
- Реанимация (категория 20)
- Любые другие

**ВАЖНО:** Фильтр по категориям (0, 8, 19) применяется ВЕЗДЕ — поступления, лиды, MQL, конверсии.

### 1.3. Период данных

- **2024–2026 годы** (по DATE_CREATE)
- **С начала года** = с 1 января 2026 по текущую дату
- **Поступления** — по дате UF_DATE_PAY_1C (без ограничения по году создания)

### 1.4. Технические ограничения

- **MIN_OPP = 11.0 ₽** — минимальная сумма сделки для учёта. Сделки 0–10 ₽ не считаются нигде.
- **Технические сделки** (WON + 0 ₽) — НЕ считаются нигде и никогда
- **WON-копии в PreSale(8) и КОМ(19)** — НЕ считаются (дубли при переходе в Sale)

### 1.5. CRM Export API

- **Эндпоинт:** `https://24.uprav.ru/web_services/crm/export.php`
- **Secret key:** `14b0fc053c141e47a5974b3859f5753f`
- **Методы:** `getDeals`, `getFormats`, `getDirections`, `getUserFieldsCrm`

- **Обогащение:** CATEGORY_NAME, STAGE_NAME, FORMAT_NAME, DIRECTION, CONTACT, COMPANY

- **UF_DATE_PAY_1C НЕ возвращается** — дозагружается через REST API (`crm.deal.get` batch)

## 2. Базовые правила

### 2.1. Деление ООМ / КОМ

Сделка считается **КОМ (Корпоративное обучение)**, если выполняется **любое** из условий:
1. **Галочка** `UF_CRM_1683882427069` = `Y` (поле «КОМ»)
2. **Формат** `UF_FORMAT` = «КОМ» (ID=19042498)
3. **Направление** `UF_CRM_1498466811` = «Корпоративное обучение» (ID=1906)
4. **Категория** = 19 «КОМ Sale»
5. **Тип обучения** `UF_CRM_1765896709800` = «КОМ» (ID=34765)

**ООМ (Открытое обучение)** = всё остальное из трёх воронок, что не КОМ.

### 2.2. Поступления (доход) — карточка 1

**Главное правило: ТОЛЬКО по дате оплаты из 1С (`UF_DATE_PAY_1C`).**

```
Поступления = сумма OPPORTUNITY по сделкам где:
  UF_DATE_PAY_1C IS NOT NULL     # дата оплаты из 1С есть
  AND OPPORTUNITY >= 11 ₽        # MIN_OPP
  AND CATEGORY_ID IN (0, 8, 19)  # только валидные категории
  (SEM не проверяется — считаются любые стадии, включая P, F, S)
```

**Срок WON (дни):** от DATE_CREATE до UF_DATE_PAY_1C, только дни ≥ 0.
- Простая средняя, взвешенная (по сумме), медиана

**Данные (09.06.2026):**
- ИТОГ: 74 927 954 ₽ / 861 сд.
- ООМ: 60 879 821 ₽ / 815 сд.
- КОМ: 14 048 133 ₽ / 46 сд.
- Средний чек: 87 024 ₽
- Медиана: 55 300 ₽
- Макс: 990 000 ₽
- Мин: 4 125 ₽
- Срок WON: 30.3 дн. (взвеш. 49.0, медиана 9)

### 2.3. Лиды — карточка 2

**Лиды = количество созданных сделок** (не объекты crm.lead).

```
is_all_lead:
  CATEGORY_ID IN (0, 8, 19)           # только валидные
  И НЕ (SEM=S AND OPP < 11)           # не тех.нулевые WON
  И НЕ (CATEGORY_ID IN (8,19) AND SEM=S)  # не WON-копии при переходе в Sale
```

**Разбивка:** Все лиды (общее кол-во) + Квал. лиды (MQL).

**Данные (09.06.2026):**
- Все лиды ИТОГ: 4 493
- Все лиды ООМ: 4 258
- Все лиды КОМ: 235
- MQL ИТОГ: 2 961
- MQL ООМ: 2 729
- MQL КОМ: 136

### 2.4. MQL / Квал. лиды — карточка 2 (внутри)

**Формула:**
```
is_qual_lead:
  CATEGORY_ID IN (0, 19)         # PreSale (8) не входит
  И НЕ (SEM=S AND OPP < 11)     # не тех.нулевые

  Для Sale (0):
    И STAGE НЕ В (NEW, UC_1YW3V2, UC_STZB49, UC_838R2R)  # не NEW, Аларм, Взят, Консульт
    (WON в Sale СЧИТАЕТСЯ как MQL)

  Для КОМ (19):
    И НЕ SEM=S                   # WON-копии при переходе в Sale
    И НЕ SEM=F                   # отказы (LOSE) — не MQL
    (всё остальное в КОМ = MQL)
```

### 2.6. Конверсия — карточка 3

Два показателя на одной карточке:
```
Конв. к лидам = WON (оплаченные) / Все лиды × 100%
Конв. к MQL   = WON (оплаченные) / MQL × 100%
```

**Данные (09.06.2026):**
- ИТОГ: 19.2% к лидам / 29.1% к MQL
- ООМ: 19.1% к лидам / 29.9% к MQL
- КОМ: 19.6% к лидам / 19.8% к MQL

### 2.6. Средний чек — карточка 4

```
Средний чек = Поступления YTD / Кол-во оплаченных сделок
```

На карточке: средний (основной), медиана, макс. чек, мин. чек.

### 2.7. Срок WON — карточка 5

От DATE_CREATE до UF_DATE_PAY_1C, только дни ≥ 0.

### 2.8. Поступления и лиды за неделю — карточки 6 и 7

**Карточка 6 — Неделя: поступления**
- Сумма оплат за текущую неделю (по UF_DATE_PAY_1C.isocalendar())
- Дельта к прошлой неделе (↑/↓ %)

**Карточка 7 — Неделя: лиды**
- Все лиды за неделю + дельта
- MQL за неделю + дельта
- Строго по дате создания (DATE_CREATE)

### 3.1. Артефакты

Блок внизу дашборда. Аномалии, требующие проверки:

| Артефакт | Что проверяем |
|:---|---|
| 🔄 Возвраты | UF_DATE_PAY_1C + LOSE + >0 |
| ⚠️ В работе с оплатой | UF_DATE_PAY_1C + P (сделка не закрыта, но оплата прошла) |
| ❓ WON без даты | WON без UF_DATE_PAY_1C |
| ⛔ Технические | WON + 0 ₽ |

## 4. Обновление данных — пошаговая инструкция

Выполнять **каждый понедельник** (или при необходимости обновить данные за неделю).

### Шаг 1. Подготовка

```bash
cd /root/.openclaw/workspace/projects/drop-dashboard-new/scripts
```

### Шаг 2. Выгрузка сделок через Export API

```bash
python3 fetch_refresh.py --full
```

⚠️ Что делает: выгружает ВСЕ сделки из CRM Export API (категории 0, 8, 19) за 2025-2026 годы.
Результат: `cache/deals_NEW.json` — обновлённый файл со всеми сделками.

### Шаг 3. Дозагрузка UF_DATE_PAY_1C

```bash
python3 fetch_pay_dates.py
```

⚠️ Что делает: дозагружает поле `UF_DATE_PAY_1C` (дата оплаты из 1С) через REST API.
**Почему отдельно:** Export API не возвращает это поле.

⏱ Длительность: ~3-5 минут (batch по 50 сделок, ~300 запросов).

**Результат:** `cache/deals_NEW.json` — дозаполнены даты оплаты.

### Шаг 4. Агрегация данных

```bash
python3 analyze_new.py
```

⚠️ Что делает: пересчитывает все метрики — поступления, лиды, MQL, конверсии, средний чек, срок WON, графики.
Результат: `cache/agg_new.json` — готовый кэш для дашборда.

**Проверка вывода:** в консоли должно быть:

**Проблема:** MQL не совпадает с ожиданием
→ Проверить `is_qual_lead()` — стадии MQL+ и исключения

### 4.3. Формат дат

Export API возвращает даты в формате `ДД.ММ.ГГГГ` (с точкой).
Старый REST API — в `ГГГГ-ММ-ДД`.
Парсер проверяет 3-й символ: если `dc[2] == '.'` — формат `ДД.ММ.ГГГГ`.
