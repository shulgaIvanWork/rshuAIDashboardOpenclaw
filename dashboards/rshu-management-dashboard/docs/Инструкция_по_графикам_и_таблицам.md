## Структура дашборда

Дашборд состоит из двух вкладок, переключаемых через `renderPage()` и `renderPageMainNew()`:

- **Основная вкладка** (`renderPage` + `drawCharts`) — KPI 3×7 + графики
- **Новая логика** (`renderPageMainNew`) — KPI 3×7 + дополнительные графики

Обе вкладки используют данные из одного API-эндпоинта `/api/data/new`.

## 1. Вкладка «Основная» — renderPage() + drawCharts()

### 1.1. KPI — 3 ряда × 7 карточек

**Что показывает:** 3 строки (ИТОГ, ООМ, КОМ) по 7 метрик YTD + данные текущей недели.

**Данные:** `data.ytd`, `data.oom_ytd`, `data.kom_ytd` (YTD), `data.prev`/`data.cur` (неделя).

**Формулы:**

| Карточка | Поле | Формула (фронт) |
|:---:|---|:---|
| 📊 Поступления YTD | `ytd.postupleniya` + `ytd.won_relevant_cnt` | Из API (`metrics()`) |
| 📋 Лиды YTD | `data.leads_ytd` + `data.qual_lead_ytd` | `is_all_lead()` + `is_qual_lead()` |
| 📈 Конверсия YTD | `ytd.conv_deal_pct` | WON / (WON+LOSE) × 100 |
| 💰 Средний чек YTD | `ytd.avg_check` + `ytd.median_check` | Сумма / кол-во + медиана |
| ⏱ Срок WON, дн. | `ytd.avg_close_days_won` | Простая средняя дней от DATE_CREATE до UF_DATE_PAY_1C |
| 📈 Неделя: поступления | `cur.postupleniya` | Сумма оплат по UF_DATE_PAY_1C за текущую ISO-неделю |
| 🎯 Неделя: лиды | `data.leads_cur` + дельта | Лиды по DATE_CREATE за неделю, дельта к прошлой |

**ООМ/КОМ split:**
- ООМ: `data.oom_*` — сделки с `IS_OOM = true` (не КОМ, CAT 0|8|19)
- КОМ: `data.kom_*` — сделки с `IS_KOM = true` (любой из 5 признаков)
- ИТОГ = ООМ + КОМ (непересекающиеся множества)

**Цвета:** ИТОГ `#1f2a44`, ООМ `#00bcd4`, КОМ `#9C27B0`

### 1.2. Воронка MQL → SQL → Сделки по неделям (ch_funnel, ch_funnel_qual)

**canvas:** `ch_funnel`, `ch_funnel_qual`
**Тип:** stacked bar

**Что показывает:** 3 слоя — MQL (синий), SQL (золотой), Оплачено (зелёный) по неделям.

**Данные:**
```javascript
mql = weeks.map(w => w.mql)   // квалифицированные лиды по DATE_CREATE
sql = weeks.map(w => w.sql)   // стадии SQL+ по DATE_CREATE  
opl = weeks.map(w => w.oplata) // оплаченные сделки по DATE_CREATE (не по дате оплаты!)
```

**Формула:**
- `w.mql` = `is_qual_lead_w()` по DATE_CREATE на неделе (Sale: MQL+ стадии, КОМ: кроме WON/LOSE)
- `w.sql` = сделки с DATE_CREATE на неделе, стадии DETAILS/PROPOSAL/2/6/WON + КОМ SQL-стадии
- `w.oplata` = сделки с DATE_CREATE на неделе, у которых есть UF_DATE_PAY_1C (оплачены когда угодно)

**Тултип:** номер недели (label_full) в заголовке, числовые значения в подписях.

### 1.3. Конверсии воронки (ch_conv, ch_conv_qual)

**canvas:** `ch_conv`, `ch_conv_qual`
**Тип:** line (с заполнением)

**Что показывает:** 2 линии — MQL→SQL % и SQL→Сделки % по неделям.

**Данные:**
```javascript
cms = weeks.map(w => w.conv_mql_sql)   // MQL→SQL %
cso = weeks.map(w => w.conv_sql_oplata)  // SQL→Оплата %
```

**Формулы (Python):**
```python
w["conv_mql_sql"] = w["sql"] / w["mql"] * 100    # если mql > 0
w["conv_sql_oplata"] = w["oplata"] / w["sql"] * 100  # если sql > 0
```

**Шкала Y:** от 0 до 180 (max).

**Цвета:** MQL→SQL — синий `#1976D2`, SQL→Оплата — зелёный `#2E7D32`

**canvas:** `ch_fmt`
**Тип:** stacked bar

**Что показывает:** распределение поступлений по форматам обучения по неделям.

**Данные (Python):**

## 4. Date Picker (фильтр периода)

**Элементы:** `#dateFrom`, `#dateTo`, `#filterBtn`

**Логика:**
1. Устанавливаются `dateFrom = '2026-01-01'`, `dateTo = today` по умолчанию
2. При изменении → `weeksInRange(weeks, dateFrom, dateTo)` — фильтр по ISO-номеру недели
3. `buildFilteredData()` пересчитывает KPI:
   - `sumField('postupleniya')` — аналог `metrics()`, но недельный
   - `sumField('oplata')` — количество оплаченных сделок
   - Остальные поля (конверсия, медиана и др.) — из оригинала (не пересчитываются)
4. `renderPageMainNew(filteredData)` — отрисовка с новыми данными

**Ограничения:** 
- Медиана, конверсия сделок, длительность WON и др. — из оригинала (не пересчитываются)
- Форматы и B2B — из оригинала
- ТОП-20 продуктов/компаний — из оригинала

## 5. Обновление данных (Refresh)

**Кнопка:** `🔄 Обновить данные`

**Процесс:**
1. `POST /api/refresh/reset` — сброс зависшего состояния
2. `POST /api/refresh` — запуск пайплайна Python
3. Polling `/api/status` каждые 5 секунд до `loading=false`
4. После завершения → `loadAll()` → перезагрузка всех данных

**Скрипты:** `run_full.py` (см. `Расчёт_KPI_3_строки_7_карточек.md`)

## 6. Графики — технические требования

### Chart.js v4
- Библиотека: `chart.js@4.4.0` (CDN)
- Плагин: `chartjs-plugin-datalabels@2.2.0` (CDN)
- Регистрация: `Chart.register(ChartDataLabels)` в начале `<script>`

### Очистка графиков
- Основная вкладка: `Object.keys(chartInstances).forEach(id => { chartInstances[id].destroy(); })` в начале `drawCharts()`
- Новая вкладка: `destroyNewCharts()` в начале `renderPageMainNew()`
- Хранилище: `chartInstances = {}` (основная), `chartInstancesNew = {}` (новая)

### Canvas ID
- Основные графики: `ch_*` (ch_funnel, ch_conv, ch_pos, ...)
- Новые графики: `newCh*` (newChFunnel, newChConv, newChPos, ...)
- НЕ пересекаются — но очистка обязательна при re-render

### Base Path
- Автоопредение: `window.location.pathname.match(/^\/([^/]+?)(?:\/|$)/)`
- Для `/rshu-management-dashboard/` → `BASE_PATH = '/rshu-management-dashboard'`
- Для самостоятельного сайта → `BASE_PATH = ''`

## 8. Известные ограничения

1. **Медиана при date-фильтре** — не пересчитывается (берётся из оригинала). Причина: недельный split чеков не хранится.
2. **Форматы при date-фильтре** — не пересчитываются. Причина: нет недельных данных по форматам.
3. **B2B при date-фильтре** — пересчитывается (суммы) из `btype_ytd` (но это заглушка на Python, не точная).
4. **Стеки "не утверждены"** — Ольга сказала, что оба стека неверны. Требуется уточнение логики.
5. **C8:LOSE в стеке 2** — пока выводится как stack2_rej_nq (отказы неКвал). Может требовать уточнения.
6. **~1700 строк в стеке 1** — ожидаемая высота на рабочих неделях. Если меньше — возможна ошибка фильтрации.
