## 1. Изменения 22.06.2026

### 1.1. Цикл сделки: ИТОГ теперь ≠ ООМ

**Проблема:** ИТОГ и ООМ показывали одинаковый avg_close_days_won.

**Причина (analyze_new.py, строки 489–496, исправлено):**
1. `durs` (используется для `avg_dur` ИТОГ) заполнялся ТОЛЬКО для ООМ-сделок. КОМ-сделки не участвовали.
2. Длительность в понедельных считалась по `CLOSEDATE`, а не по `UF_DATE_PAY_1C`.

**Исправление:**
- `durs` включает все сделки (ООМ + КОМ)
- `oom_durs` — только ООМ
- `kom_durs` — только КОМ
- Длительность считается по `PAY_DT - DC` (как в YTD), а не `CL - DC`

**После:** ИТОГ = 29.2 дн, ООМ = 27.3 дн, КОМ = 82.7 дн

**Коммит:** `657e971`

### 1.2. Конверсия: metrics() проверяет YEAR

**Проблема:** agg.json показывал won_relevant_cnt=892, фронт пересчитывал в 884 (расхождение 8 сд).

**Причина:** `metrics()` не проверяла `PAY_DT.year == YEAR`. 8 сделок с `UF_DATE_PAY_1C=2025`, созданных в 2026, попадали в YTD 2026.

**Исправление (analyze_new.py):**
```python
paid = [r for r in subset if is_paid(r) and pred(r) and r["PAY_DT"].year == YEAR]
```

**Правило:** Сделки с PAY_DT < DC — ошибка CRM. Считать в периоде оплаты.

**После:** metrics = 884 сд ✅ сходится с понедельными. Конверсия = 18.7% / 29.3%

**Коммит:** `d8970d8`

### 1.3. 6-я карточка КПЭ: «Оплачено сделок»

В блок «Неделя: поступления» добавлен второй ряд с количеством оплаченных сделок за неделю.

## 4. Валидные категории и фильтры

### 4.1. Участвующие категории
```python
VALID_CATS = {0, 8, 19}
```
| ID | Название | Участвует |
|:--:|----------|:---------:|
| 0 | Sale | ✅ |
| 8 | Pre Sale | ✅ |
| 19 | КОМ (Sale) | ✅ |
| 9, 10, 12, 13, 20 | Остальные | ❌ |

### 4.2. Минимальная сумма
```python
MIN_OPP = 11.0  # сделки 0-10 ₽ не учитываются
```

### 4.3. Признаки КОМ (any из 5)
```python
is_kom = (
    UF_CRM_1683882427069 == Y/1  # галочка
    or UF_FORMAT == 19042498      # формат
    or UF_CRM_1498466811 == 1906  # направление
    or CATEGORY_ID == 19          # категория
    or UF_CRM_1765896709800 == 34765  # тип обучения
)
```

### 4.4. Оплаченная сделка (is_paid)
```python
is_paid = (
    UF_DATE_PAY_1C is not null
    and OPPORTUNITY >= 11.0
    and CATEGORY_ID in (0, 8, 19)
)
```

### 4.5. Лиды (is_all_lead)
- CAT IN (0,8,19)
- Не тех.нулевые (WON + OPP < 11)
- Не WON-копии (CAT 8/19 + SEM=S)

### 4.6. MQL (is_qual_lead)
- Sale (0): все стадии кроме NEW/Аларм/Взят/Консульт
- PreSale (8): не входит
- КОМ (19): всё кроме WON и LOSE

### 4.7. Неделя
- По **дате оплаты** (UF_DATE_PAY_1C): `date.isocalendar()[1]` (ISO-неделя)
- По **дате создания** (DATE_CREATE): для лидов, MQL, воронок

## 5. Структура новой вкладки (сверху вниз)

### 5.1. KPI — 3 ряда × 7 карточек

**ИТОГ (navy), ООМ (бирюзовый), КОМ (фиолетовый)**

| № | Карточка | Поле | Формула |
|:-:|----------|------|---------|
| 1 | 📊 Поступления | `postupleniya` + `won_relevant_cnt` | Сумма OPP оплаченных + кол-во |
| 2 | 📋 Лиды всего | `leads_ytd` + `conv_deal_pct` | `is_all_lead()` + дельта к MQL |
| 3 | 📈 Конверсия | `conv_deal_pct` | WON / (WON+LOSE) × 100 |
| 4 | 💰 Средний чек | `avg_check` + `median_check` | Сумма / кол-во + медиана |
| 5 | ⏱ Цикл сделки | `avg_close_days_won` | Дней от DATE_CREATE до UF_DATE_PAY_1C |
| 6 | 📈 Неделя: поступления | последняя неделя | Дельта к прошлой в % |
| 7 | 🎯 Неделя: лиды | последняя неделя | Дельта к прошлой |

### 5.2. Поступления + Форматы (twocol)
- **Слева:** график поступлений по неделям (bar, `newChPos`)
- **Справа:** пончик форматов YTD (`newChFmt`) + таблица форматов

### 5.3. Воронка (созданные) — `newChFunnel2`
- Stacked bar по неделям: статус сделок, созданных на неделе W
- 7 слоёв: Оплата, Счёт, Отказы неКвал, Отказы, НеКвал, MQL, SQL

### 5.4. Воронка (активные) — `newChFunnel`
- Stacked bar по неделям: активные сделки на неделе W
- 7 слоёв: те же

### 5.5. Ряд 1 (twocol) — ТИП КЛИЕНТА + ИСТОЧНИКИ
- **Слева:** пончик B2B/B2C + таблица (Период, Тип, Шт, Сумма, Средний чек, Доля,%)
- **Справа:** пончик источников + таблица

### 5.6. Средний чек по неделям (full width)
- Две линии: ООМ (бирюзовый), КОМ (фиолетовый)
- Данные: `weeks[].oom_avg_check`, `weeks[].kom_avg_check`

### 5.7. Ряд 2 (twocol) — ОПЛАТЫ/ОТКАЗЫ
- **Слева:** два пончика (ООМ и КОМ) с таблицами
- **Справа:** Оплаты vs Отказы по неделям (bar, `newChCnt`)

### 5.8. MBA таблица
- Типы MBA-программ по поступлениям

### 5.9. Недельная таблица
- Полная сводка по каждой неделе: Лиды, MQL, SQL, Оплаты, Поступления, конверсии

### 5.10. Ключевые выводы
- YTD картина, неделя, лидеры, рекомендации

### 5.11. Артефакты
- Загрузка из `/api/artifacts`

| 12 | **SQL→Счёт** | `w.conv_sql_invoice` | `w.invoice_cnt / w.sql * 100` |
| 13 | **Счёт→Оплата** | `w.conv_invoice_oplata` | `w.oplata / w.invoice_cnt * 100` |
| 14 | **Лид→Оплата** | рассчитывается на фронте | `w.oplata / w.leads * 100` |

### 14.2. Дельта Лид→Оплата

**Формула:**
```javascript
diff = текущая_конверсия - следующая_конверсия (нижняя строка таблицы = более старая неделя)
if diff > 0 → ↑+X.X% (зелёный #2E7D32)
if diff < 0 → ↓X.X% (красный #C62828)  
if diff = 0 → →0.0% (серый #888)
```

**Первая строка (последняя неделя):** дельта к предпоследней неделе (следующая строка вниз).

**Последняя строка (самая старая неделя):** без дельты.

### 14.3. ИТОГО YTD

```javascript
tL = sum(w.leads)
tM = sum(w.mql)
tS = sum(w.sql)
tO = sum(w.oplata)  // общее количество оплаченных за YTD
tP0 = sum(w.postupleniya)  // общая сумма поступлений YTD

// Конверсии ИТОГО:
Лиды→MQL   = tM / tL * 100
MQL→SQL    = tS / tM * 100
SQL→Счёт   = tO / tS * 100  // использется o = оплата (аппроксимация)
Счёт→Оплата = tO / ... (не рассчитывается для итога)
Лид→Оплата = tO / tL * 100
```

**Важные отличия:**
- `w.oplata` — количество сделок, созданных на неделе W и впоследствии оплаченных (по DATE_CREATE)
- `w.won_cnt` — количество оплаченных по UF_DATE_PAY_1C на неделе W (по дате оплаты)
- `w.postupleniya` — сумма по UF_DATE_PAY_1C на неделе (по дате оплаты)

Эти три поля могут не совпадать для одной недели — сделка создана на W1, оплачена на W5.

## 22. Важные правила

1. **Источники — по ID, не по названию.** Справочник в `dicts.json["sources"]`.
2. **Медиана убрана с графика среднего чека.** Линии ООМ и КОМ.
3. **MMBA с 0 суммой не показывается.** Если появятся — в артефактах.
4. **Средняя длительность — только дни >= 0.** Отрицательные — артефакт.
5. **Неделя — ISO по дате оплаты (UF_DATE_PAY_1C).** Для лидов — по DATE_CREATE.
6. **Конверсии воронки — только на основной вкладке.**
7. **Конверсия в счёт по регистрациям:** 53.6% (с учётом автооплат = INV_DT=PAY_DT).
8. **Цикл счёта:** среднее дней от создания до даты счёта (с учётом автооплат).
9. **Две сделки 321458 и 321895** — принудительно Видеокурс.
10. **Пайплайн запускать только по команде.**
