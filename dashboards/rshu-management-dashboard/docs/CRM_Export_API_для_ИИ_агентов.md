# CRM Export API для ИИ-агентов

Файл: `/web_services/crm/export.php`
Назначение: безопасная выдача справочных данных и ограниченных выборок сделок Bitrix24 CRM для ИИ-агентов.

**Текущий статус (19.06.2026):** Используется как дополнительный источник в `fetch_export.py`.
Основной источник — REST API (`fetch_rest.py`).
Export API не возвращает STAGE_SEMANTIC_ID и UF_* поля, поэтому данные из Export
имеют меньший приоритет и перезаписываются данными из REST API.

## Общий формат запроса

Метод: `POST`
Content-Type: `application/x-www-form-urlencoded`

Обязательные параметры:

| Параметр | Тип | Описание |
|---|---:|---|
| `secret` | string | Секретный ключ доступа к API. |
| `action` | string | Действие: `getDeals`, `getFormats`, `getDirections`, `getUserFieldsCrm`. |
| `data` | array | Параметры действия. Для справочников может быть пустым массивом. |

Стандартный ответ:

```json
{
 "success": true,
 "data": {},
 "errors": []
}
```

## action=getDeals

Возвращает список сделок CRM с безопасной пагинацией, нормализацией `SELECT`, `FILTER`, `SORT` и опциональным обогащением контактами, компаниями и товарами.

### Пагинация

```php
'nav' => [
 'limit' => 10,
 'offset' => 0,
]
```

Ограничения:
- Лимит по умолчанию: `10`
- Максимальный лимит: `50`
- Максимальный offset: `5000`

### SELECT

Если `SELECT` не передан — безопасный набор по умолчанию.

Запрещено: `'*'`, `'UF_*'`.

### FILTER

Допустимые поля: `ID`, `CATEGORY_ID`, `STAGE_ID`, `ASSIGNED_BY_ID`, `CONTACT_ID`, `COMPANY_ID`, `DATE_CREATE`, `DATE_MODIFY`, `BEGINDATE`, `CLOSEDATE`, `UF_FORMAT`, `UF_CRM_1498466811`, `UF_CRM_*`.

Операторы: `=`, `>=`, `<=`, `>`, `<`.

### SORT

Поля: `ID`, `DATE_CREATE`, `DATE_MODIFY`, `BEGINDATE`, `CLOSEDATE`, `STAGE_ID`, `CATEGORY_ID`.
Направление: `ASC` или `DESC`.

### WITH_PRODUCTS

Режим `WITH_PRODUCTS=Y` — загружает товары и модули сделки.
Использовать только точечно с `limit <= 5`.

### Рекомендации для ИИ-агента

1. Всегда запрашивать данные маленькими страницами: `limit` от `5` до `20`.
2. Не использовать широкие выборки без фильтра.
3. Для поиска конкретной сделки использовать фильтр по `ID`.
4. Для периодов обязательно использовать фильтр по датам.
5. Для продолжения пагинации использовать `data.nav.nextOffset`.
6. `WITH_PRODUCTS=Y` — только при необходимости и с маленьким `limit`.

## action=getFormats

Возвращает справочник форматов из инфоблока `149`.

## action=getDirections

Возвращает список направлений из пользовательского поля `UF_CRM_1498466811`.

## action=getUserFieldsCrm

Возвращает список пользовательских полей сделок CRM.

## Важные ограничения

- Не запрашивать больше `50` сделок за один запрос.
- Не использовать `SELECT = ['*', 'UF_*']`.
- Не выполнять массовую выгрузку всех сделок без фильтров.
- `WITH_PRODUCTS=Y` — только при необходимости (лимит 5).
- При ошибке `invalid_key` не повторять запрос бесконечно.
- При пустом `nextOffset` — следующей страницы нет.
