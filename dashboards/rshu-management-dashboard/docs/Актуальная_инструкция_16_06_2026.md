## 2. Воронки (категории)

Участвуют **3 воронки** — всё остальное исключено:

| ID | Название | Описание |
|---:|---|:---|
| 0 | **Sale** | Основные продажи |
| 8 | **Pre Sale** | Предпродажная подготовка |
| 19 | **КОМ (Sale)** | Корпоративное обучение |

**Исключены:** Post Sale (9), Аккаунтинг (10), Отказы (12), Repeat Sale (13), Реанимация (20) и любые другие.

**MIN_OPP = 11.0 ₽** — сделки 0–10 ₽ не учитываются нигде.

## 3. Ключевые метрики

### 3.1. ООМ / КОМ

Сделка считается **КОМ**, если выполняется **любое** из:
1. Галочка `UF_CRM_1683882427069` = `Y`
2. Формат `UF_FORMAT` = «КОМ» (ID=19042498)
3. Направление `UF_CRM_1498466811` = «Корпоративное обучение» (ID=1906)
4. Категория = 19
5. Тип обучения `UF_CRM_1765896709800` = «КОМ» (ID=34765)

**ООМ** = всё остальное из категорий 0, 8, 19, что не КОМ.

### 3.2. Поступления (доход)

```
Поступления = сумма OPPORTUNITY по сделкам где:
  UF_DATE_PAY_1C IS NOT NULL     # дата оплаты из 1С
  AND OPPORTUNITY >= 11.0 ₽      # MIN_OPP
  AND CATEGORY_ID IN (0, 8, 19)  # только валидные
  (SEM не проверяется — P, F, S — любые)
```

**Срок WON** = от DATE_CREATE до UF_DATE_PAY_1C (дни ≥ 0).  
Средняя, взвешенная, медиана.

### 3.3. Лиды

**Лиды = количество созданных сделок** (crm.deal, не crm.lead).

```
is_all_lead:
  CATEGORY_ID IN (0, 8, 19)
  И НЕ (SEM=S AND OPP < 11)         # тех.нулевые WON
  И НЕ (CATEGORY_ID IN (8,19) AND SEM=S)  # WON-копии при переходе в Sale
```

### 3.4. MQL / Квал. лиды

```
is_qual_lead:
  CATEGORY_ID IN (0, 19)            # PreSale (8) НЕ входит
  И НЕ (SEM=S AND OPP < 11)

  Для Sale (0):
    И STAGE НЕ В (NEW, UC_1YW3V2, UC_STZB49, UC_838R2R)
    (WON в Sale СЧИТАЕТСЯ)

  Для КОМ (19):
    И НЕ SEM=S (WON-копии)
    И НЕ SEM=F (LOSE)
    (всё остальное в КОМ = MQL)
```

**Стадии ДО MQL (исключаются):** NEW, UC_1YW3V2 (Аларм), UC_STZB49 (Взят), UC_838R2R (Консульт).

**Стадии MQL+ в Sale:** UC_4RJOR4 (MQL), DETAILS (SQL), PROPOSAL, 2, 6, WON, LOSE, UC_F2YC3N, UC_VKPN0N, UC_W6SCHG, UC_670ME2.

### 3.5. Воронка (5 этапов по неделям)

| Этап | Code | Детали |
|:---:|---|---|
| Лиды | `is_all_lead` | CAT IN (0,8,19) по DATE_CREATE |
| MQL | `is_qual_lead` | Sale: MQL+; КОМ: все кроме WON/LOSE |
| SQL | стадии SQL+ | **Точно:** DETAILS, PROPOSAL, 2, 6, WON. **С счётом:** LOSE, UC_F2YC3N, UC_W6SCHG, UC_670ME2, UC_VKPN0N. **КОМ:** EXECUTING, C670BC, I443UQ (точно), AL0Z6B, W4ML6H, LOSE — с UF_CRM_5D133690E1 |
| Счёт | UF_CRM_1753272713011 | Не КОМ |
| Оплата | UF_DATE_PAY_1C | CAT IN (0,8,19) + OPP >= 11 |

### 3.6. Конверсия

Два показателя:
```
Конв. к лидам = WON (оплаченные) / Все лиды × 100%
Конв. к MQL   = WON (оплаченные) / MQL × 100%
```

### 3.7. Средний чек

```
Средний чек = Поступления YTD / Кол-во оплаченных сделок
```

На карточке: средний, медиана, макс, мин.

### 3.8. B2B / B2C

| Условие | Тип |
|:---|---|
| Есть COMPANY_ID (не пустой, не "0") | B2B |
| Категория = КОМ | B2B |
| Остальное | B2C |

### 3.9. Форматы

Приоритет: `UF_FORMAT` (инфоблок 149) → fallback по ключевым словам в названии.

### 3.10. Менеджеры — исключения

| ID | Менеджер | Действие |
|:---:|---|---|
| 527 + 516 | Щеткина + Гайдукова | → «Автооплаты» (одна строка) |
| 1 | [БОТ] James Bond | Исключить полностью |
| 27119 | Мария Кулевцова | Исключить (ОЗК, тех.сделки) |
| 21286 | Дмитрий Афанасьев | Исключить (лид-менеджер) |

### 3.11. WON-копии в PreSale и КОМ

**Критическое правило:** при переходе сделки из PreSale(8) или КОМ(19) в Sale(0) — в исходной категории остаётся копия WON. Эти копии:
- НЕ считаются в лиды
- НЕ считаются в MQL
- НЕ имеют UF_DATE_PAY_1C (не участвуют в поступлениях)

## 5. Обновление данных — инструкция

Выполняется вручную через кнопку «🔄 Обновить данные» на дашборде.  
Либо через консоль:

```bash
# Папка с управленческим дашбордом
cd /root/.openclaw/workspace/projects/dashboards/rshu-management-dashboard

# Полная пересборка (7 шагов)
python3 scripts/run_full.py

# Или пошагово:
python3 scripts/fetch_refresh.py               # 1. Сделки (Export API)
python3 scripts/fetch_pay_dates.py              # 2. Дозагрузка UF_DATE_PAY_1C (REST API)
python3 scripts/fetch_dicts.py                  # 3. Справочники
python3 scripts/fetch_companies_ext_batch.py    # 4. Компании (адреса)
python3 scripts/fetch_contacts_batch.py         # 5. Контакты
python3 scripts/fetch_leads.py                  # 6. Лиды
python3 scripts/analyze_new.py                  # 7. Анализ → agg_new.json

# Копирование agg_new.json → agg.json (сервер читает agg.json)
cp cache/agg_new.json cache/agg.json

# Перезапуск сервера
pm2 restart clover-web
```

⏱ **Длительность:** ~10-15 минут (основное время — Export API + REST API дозагрузка).

### Шаги после обновления

1. Открыть https://uprav.tech/rshu-management-dashboard/
2. Проверить KPI: ИТОГ (ООМ+КОМ) = ООМ + КОМ ✅
3. Проверить артефакты (блок внизу)
4. Проверить недельную дельту (реалистична?)
