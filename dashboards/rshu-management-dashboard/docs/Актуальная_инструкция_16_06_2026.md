## 3. Пайплайн обновления

```bash
# Полный цикл:
cd /root/.openclaw/workspace/projects/dashboards/rshu-management-dashboard
python3 scripts/run_full.py
cp cache/agg_new.json cache/agg.json
pm2 restart clover-web
```

### Шаг 1: fetch_rest.py — REST API
- `crm.deal.list` с next-токеном (без лимита offset)
- Фильтр: >=DATE_CREATE 2025-01-01, CAT IN (0,8,19)
- Все поля: STAGE_SEMANTIC_ID (нет None!), UF_*, UF_DATE_PAY_1C
- ~28,300 сделок за 2025-2026
- → cache/deals_rest.json

### Шаг 2: fetch_export.py — Export API + OLD
- Export API загружает категории 0, 8, 19
- Мерж: REST > Export > OLD (приоритет полей)
- OLD архив добавляет ~20 сделок, которых нет в REST
- → cache/deals_NEW.json

### Шаг 3: fetch_dicts.py — справочники
- → cache/dicts.json

### Шаг 4: analyze_new.py — анализ
- Читает deals_NEW.json, dicts.json
- Считает KPI, недели, воронки, артефакты
- → cache/agg_new.json

## 4. Основные правила

### 4.1. Минимальная сумма
```python
MIN_OPP = 11.0  # сделки 0-10 ₽ не учитываются
```

### 4.2. КОМ (любое из условий)
1. `UF_CRM_1683882427069` == Y/1
2. `UF_FORMAT` == 19042498
3. `UF_CRM_1498466811` == 1906
4. `CATEGORY_ID` == 19
5. `UF_CRM_1765896709800` == 34765

### 4.3. Лиды
- Только CAT IN (0,8,19)
- Не тех.нулевые (WON + OPP < 11)
- Не WON-копии (CAT 8/19 + SEM=S)

### 4.4. MQL
- Sale (0): все стадии кроме NEW/Аларм/Взят/Консульт
- PreSale (8): не входит в MQL
- КОМ (19): всё кроме WON (S) и LOSE (F)

### 4.5. Поступления
- Только с UF_DATE_PAY_1C
- CAT IN (0,8,19), OPP >= 11
- Неделя по ISO-дате оплаты

## 5. REST API vs Export API

| Критерий | REST API | Export API |
|----------|:--------:|:----------:|
| **STAGE_SEMANTIC_ID** | ✅ Корректно | ❌ None |
| **UF_CRM_* поля** | ✅ Корректно | ❌ Нет |
| **UF_DATE_PAY_1C** | ✅ Есть | ❌ Нет |
| **Пагинация** | ✅ next-токен (без лимита) | ❌ лимит offset=5000 |
| **Скорость** | ~7-8 мин | ~4-5 мин |
| **Статус** | Основной источник | Дополнительный |
