# DECISIONS — 2026-06-22

## Зафиксированные решения

### 1. Сделки с PAY_DT раньше DC — считать в периоде оплаты
- **Контекст:** 8 сделок с UF_DATE_PAY_1C=2025, DATE_CREATE=2026
- **Решение:** Не включать в YTD 2026. Считать в периоде, указанном в UF_DATE_PAY_1C. Выводить в артефакты.
- **Причина:** Б24 не позволяет ставить дату создания в прошлое. PAY_DT < DC — ошибка ведения CRM менеджером.
- **Реализация:** `r["PAY_DT"].year == YEAR` в `metrics()`

### 2. Цикл сделки считать по UF_DATE_PAY_1C
- **Решение:** Длительность = (PAY_DT - DATE_CREATE).days
- **Где:** и в YTD metrics(), и в понедельных данных
- **Было:** в понедельных использовался CLOSEDATE, в YTD — PAY_DT

### 3. durs (avg_dur для ИТОГ) должен включать КОМ-сделки
- **Решение:** `durs` — все сделки (ООМ + КОМ), `oom_durs` — только ООМ, `kom_durs` — только КОМ
- **Было:** `durs` = только ООМ, из-за чего avg_dur ИТОГ = avg_dur ООМ

### 4. Определение КОМ: 5 признаков через OR
- **Состав:** галочка `UF_CRM_1683882427069`, формат `19042498`, направление `1906`, категория `19`, тип обучения `34765`
- **Дашборд:** rshu-management-dashboard
