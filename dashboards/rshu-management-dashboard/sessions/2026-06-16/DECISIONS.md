## 1. Стек 1 — Воронка продаж (активные сделки)

### Что показывает
Загрузку менеджеров: сколько сделок активно на каждой неделе, независимо от даты создания.

### Высота столбца
Все сделки, которые:
- CAT_ID IN (0, 8, 19) — только валидные категории
- DATE_CREATE ≤ sun недели (созданы не позже)
- НЕ оплачены до mon (UF_DATE_PAY_1C < mon → excluded)
- НЕ проиграны до mon (SEM=F + CLOSEDATE < mon + CLOSED=Y → excluded)
- НЕ формально закрыты до mon (CLOSED=Y + CLOSEDATE < mon → excluded)

**Ожидаемая высота:** ~1.4-1.5k на рабочих неделях

### 6 сегментов (снизу вверх)

| Позиция | Сегмент | Цвет | Правило |
|:---:|---|:---:|---|
| 6 (верх) | 🟩 **Оплата** | `#43A047` | UF_DATE_PAY_1C на неделе + OPP ≥ 11 |
| 5 | 🟪 **Счёт** | `#7E57C2` | UF_CRM_1753272713011 на неделе |
| 4 | 🟦 **SQL** | `#1A237E` | Активна на неделе, стадия SQL+ |
| 3 | 🔵 **MQL** | `#42A5F5` | Активна на неделе, стадия MQL |
| 2 | 🟨 **НеКвал** | `#FFD54F` | Активна на неделе, стадия до MQL |
| 1 (низ) | 🟥 **Отказы** | `#E53935` | CLOSEDATE на неделе + проиграно |

### Стадии для SQL (стека, НЕ KPI):
- Sale: DETAILS, PROPOSAL, 2, 6
- КОМ: EXECUTING, UC_C670BC, UC_I443UQ
- ❌ WON — НЕ входит (оплата или excluded)
- ❌ LOSE, F2YC3N — НЕ входит

### Стадии для MQL (стека, НЕ KPI):
- Sale: UC_4RJOR4 (Маркетинговый лид) — **единственная**
- PreSale: всё в работе (кроме WON-копий)
- КОМ: всё кроме WON/LOSE/EXECUTING
- ❌ DETAILS, PROPOSAL, 2, 6, WON — НЕ входят (это SQL)
- ❌ LOSE, F2YC3N, VKPN0N, W6SCHG, 670ME2 — НЕ входят (отказы/отложенные)

### Стадии для НеКвал (стека):
- NEW, UC_1YW3V2 (Аларм), UC_STZB49 (Взят), UC_838R2R (Консульт)
- PreSale: если не SQL и не MQL

### Приоритет (одна сделка = один сегмент)
Проверка сверху вниз:
1. Оплата (точная дата)
2. Счёт (точная дата)
3. Отказ (точная дата)
4. Не был оплачен/проигран/закрыт до недели → классификация по стадии:
   - SQL → MQL → НеКвал

## 2. Стек 2 — Воронка маркетинга (созданные на неделе)

### Что показывает
Эффективность лидогенерации: из сделок, созданных на неделе W, какой у них статус на сегодня.

### Высота столбца
Сделки, созданные на неделе W (DATE_CREATE в mon-sun), CAT_ID IN (0,8,19).

### Сегменты
Те же 6, что и в стеке 1, но:
- Оплата: UF_DATE_PAY_1C ≤ sun (не обязательно на этой неделе — может быть позже)
- Счёт: UF_CRM_1753272713011 ≤ sun
- Отказ: SEM=F + CLOSED=Y (за всё время)
- SQL/MQL/НеКвал: по текущей стадии (те же правила, что в стеке 1)

## 3. KPI — Карточки 3 строки × 7 карточек

### 3.1. Деление ООМ/КОМ
**5 признаков КОМ (any of):**
1. UF_CRM_1683882427069 = Y
2. UF_FORMAT = 19042498 (КОМ)
3. UF_CRM_1498466811 содержит 1906 (Корп. обучение)
4. CATEGORY_ID = 19
5. UF_CRM_1765896709800 = 34765 (КОМ)

**ООМ** = всё остальное из CAT 0, 8, 19 (не КОМ)

### 3.2. Поступления (карточка 1)
UF_DATE_PAY_1C есть + OPP ≥ 11 + CAT IN (0,8,19)
SEM не проверяется

### 3.3. Лиды (карточка 2)
**is_all_lead:** CAT IN (0,8,19), не тех.нулевые WON (OPP<11), не WON-копии в 8|19

**is_qual_lead (MQL):**
- Sale: MQL+ стадии (UC_4RJOR4, DETAILS, PROPOSAL, 2, 6, WON, LOSE, F2YC3N, VKPN0N, W6SCHG, 670ME2)
  - ❌ NEW, UC_1YW3V2, UC_STZB49, UC_838R2R
- КОМ: все кроме WON (S) и LOSE (F)
- PreSale (8): НЕ входит в MQL

### 3.4. Медиана
Простая медиана: сортировка чеков по OPP, элемент посередине

## 5. Ограничения

- MIN_OPP = 11.0 ₽ (сделки 0-10 нигде не учитываются)
- VALID_CATS = {0, 8, 19}
- Export API не возвращает UF_* поля → дозагружаем через fetch_kom_enrich.py
- Расчет YTD: с 1 января по сегодня
- Недели: ISO-недели (isocalendar)
