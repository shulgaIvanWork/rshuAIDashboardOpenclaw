# ТЗ для IT: Настройка BI-отчётности в Bitrix24

## 1. Проблемы текущего REST API

### 1.1. Ограничения вебхуков
- Вебхук `479/a98j...` **не поддерживает фильтрацию** по пользовательским полям (`UF_*`)
- Новый вебхук `516/k1cd...` работает лучше, но есть ограничения
- **Нужно:** вебхук с полными правами на чтение всех кастомных полей, включая фильтрацию

### 1.2. Поля, недоступные через REST API

| Поле в интерфейсе | API-поле | Статус |
|---|---|---|
| **Направление обучения** | `UF_CRM_1744273716729` | ✅ Есть, но пусто у 70% сделок |
| **Формат (текстом)** | `UF_FORMAT` (ID инфоблока) | ⚠️ Только ID, названия не читаются |
| **Название продукта (чистое)** | `UF_CRM_1697096074` | ✅ Есть |
| **TITLE_NAME (чистое название)** | — | ❌ Нет в REST API |
| **Тип обучения** | `UF_CRM_1498466811` (ID) | ⚠️ Только ID |
| **Дата оплаты из 1С** | `UF_DATE_PAY_1C` | ✅ Работает с новым вебхуком |
| **Формат (СДО/очный/онлайн)** | — | ❌ Нет текстового поля |

### 1.3. Фильтрация
- `<`, `>`, `>=`, `<=` по `UF_*` полям — **не работают** на многих вебхуках
- По `DATE_CREATE` — работает
- По `CLOSEDATE` — работает

## 2. Требования к BI-решению

### 2.1. Источники данных (3 системы)

```
1. Яндекс.Метрика (счётчик 1207553)
   Данные: визиты, просмотры, посетители, источники трафика
   Связь: visit_id (через Roistat)

2. Roistat (проект 229682)
   Данные: заказы, звонки коллтрекинга, visit_id
   Связь: visit_id → Метрика, url/deal/show/ID → Bitrix24

3. Bitrix24 (воронка Sale, категория 0)
   Данные: сделки, оплаты, статусы, продукты
   Связь: ID сделки ← Roistat url
```

### 2.2. Какие отчёты нужны

#### А. Воронка продаж (сквозная)
```
Метрика (визиты) → Roistat (заявки/звонки) → Bitrix24 (сделки → WON)
```
- По источникам трафика
- По дням/неделям/месяцам
- Конверсия на каждом этапе

#### Б. Рейтинг продуктов (ежемесячный)
- Оплаченные сделки за месяц (по `UF_DATE_PAY_1C`)
- Группировка по продукту (чистое название)
- Разбивка по форматам (СДО/очный/онлайн)
- Исключение: Корпоративное обучение, ILP (выводить отдельно)

#### В. Коллтрекинг
- Звонки по дням + визиты на сайт
- Дозвон, средняя длительность
- По источникам

#### Г. Конверсия и метрики
- Визит → Заявка → Оплата
- Средний чек
- Динамика по периодам

### 2.3. Логика расчётов

#### Фильтры обязательные:
1. Только воронка **Sale** (categoryId=0)
2. Сумма > 0 (исключить технические)
3. Не копии
4. Исключить **Корпоративное обучение** (направление)
5. ILP — выводить отдельным блоком

#### Артефакты (правило от 02.06.2026):
При поиске по `UF_DATE_PAY_1C`:
- **S (WON)** → основной рейтинг ✅
- **P (в работе)** + UF_DATE_PAY_1C → артефакт ⚠️ (частичная оплата/рассрочка)
- **F (проиграно)** + UF_DATE_PAY_1C → артефакт ⚠️ (возврат клиенту)

Артефакты выводить отдельным блоком с пометкой «*».

#### Форматы обучения:
- СДО: UF_FORMAT in (19042469)
- Очный: UF_FORMAT in (19042467)
- Онлайн: UF_FORMAT in (19042468)

### 2.5. Что нужно доработать в Bitrix24

1. **Добавить поле TITLE_NAME** — чистое название продукта (без дат, городов, договоров)
2. **Заполнить направление обучения** (`UF_CRM_1744273716729`) для всех сделок (сейчас заполнено ~30%)
3. **Создать текстовое поле "Формат"** (СДО/очный/онлайн) — или обеспечить доступ к инфоблоку 149
4. **Обеспечить доступ к товарным позициям** — направление обучения может храниться там
5. **API-доступ**: вебхук с правами на чтение всех UF-полей с поддержкой фильтрации

### 2.6. Задокументированные ошибки API

1. `UF_CRM_1744273716729` (Направление обучения) — пусто у ~70% сделок, хотя в карточке B24 заполнено
2. `UF_FORMAT` — только ID (19042467/68/69/98), текстовые названия через REST не получить
3. Поле КОМ (галочка Да/Нет) — не найдено в REST API. Возможный кандидат: `UF_CRM_1715012426921`, но не подтверждено
4. Поле TITLE_NAME — не существует в REST API, хотя есть в интерфейсе карточки сделки
5. Названия форматов (СДО/очный/онлайн) — хранятся в инфоблоке (IBLOCK_ID=149), недоступны через REST
6. `crm.deal.userfield.list` не возвращает русские названия полей (EDIT_FORM_LABEL пустой)
7. Фильтрация по кастомным `UF_*` полям — работает только с вебхуками, имеющими полные права (новый вебхук 516 работает, старый 479 — нет)
