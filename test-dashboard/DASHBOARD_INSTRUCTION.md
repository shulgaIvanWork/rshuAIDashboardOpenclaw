#### 5.1. Сводка мотивации
- **Данные:** `data/motivations.json` (из Google Sheets «Мотивации ДРОП 2026», лист с gid=334964199)
- **Структура:** 5 месяцев (Январь–Май 2026)

  - При выполнении: 3% с суммы плана + 6% с дельты перевыполнения
  - При недовыполнении: бонус уменьшается (отрицательная дельта)
- **Фильтр:** по месяцам (кнопки Янв–Май, «Все месяцы»)

#### 5.2. Анализ поступлений: Входящий vs Исходящий
- **Данные:** `data/export_analysis.json` (из Bitrix24 через новый вебхук 516)
- **Источники данных:** сделки B24 с UF_DATE_PAY_1C за 2026, категории Sale/Аккаунтинг/RepeatSale/Реанимация
- **Классификация:**
  - **Входящий трафик:** OPENLINE, VK, WhatsApp, заявки с сайта, коллтрекинг, регистрации, демо-уроки и т.д. (всё, что не исходящее)
  - **Исходящий трафик:** Аккаунтинг, RepeatSale, Реанимация, Upsale, холодная база (проверка по категории 10,13,20 и ключевым словам в источнике)

#### 5.3. Анализ поступлений: КОМ vs Остальные
- **Данные:** КОМ из motivation.json (колонка «доля КОМ» × факт), так как через REST B24 поле КОМ не читается
- **Причина:** В B24 формат «КОМ» хранится в инфоблоке (IBLOCK_ID=149), недоступном через REST API. Через Google Sheets-экспорт определяется по колонке «Формат» = «КОМ»

#### 5.4. Пересчёт мотивации (КАЛЬКУЛЯТОР)
- **Цель:** Сравнить текущую формулу бонуса с новой схемой (разные проценты для входящего/исходящего/КОМ)
- **Вводные поля:**
  - 📞 Входящий: X% (по умолч. 3%)
  - 📤 Исходящий: Y% (по умолч. 5%)
  - 💼 КОМ: Z% (по умолч. 2%)
  - План: редактируемое поле для каждого менеджера
- **Расчёт:**
  - **Текущий бонус:** `Факт × 6% − План × 3%` (формула из таблицы)
  - **Новый бонус:** `Входящий × X% + Исходящий × Y% + КОМ × Z%`
  - **Разница:** Новый бонус − Текущий бонус
- **Фильтр:** по месяцам (Янв-Май, «Все» — суммирует по всем месяцам)
- **Кнопка** «🔁 Пересчитать» — обновляет все расчёты по текущим введённым данным
- **Гонка данных:** renderRecalcMotivation вызывается при загрузке обоих наборов данных (motivationData + exportAnalysisData), чтобы избежать состояния гонки

## 6. Логика расчётов

### Формула бонуса (текущая)
```
Бонус = Факт × 6% − План × 3%
```
Где:
- Если факт ≥ план: `план × 3% + (факт − план) × 6%`
- Если факт < план: та же формула (дельта отрицательная)

### Классификация трафика 
**Исходящий** (проверка по source_id + category_id):
- Категории: 10 (Аккаунтинг), 13 (RepeatSale), 20 (Реанимация)
- Ключевые слова в источнике: аккаунтинг, repeatsale, репитсейл, реанимация, upsale, апсейл, очная/холодная база, холодные звонки, компенсация, подарок

**КОМ** (берётся из мотивации, не из B24):
- Причина: через REST API B24 не отдаёт текстовое значение формата
- В Google Sheets: колонка «доля КОМ» в мотивационном листе

**Входящий:** всё остальное, не вошедшее в исходящий и КОМ

### Сравнение имён
Поскольку B24 отдаёт «Имя Фамилия», а мотивация — «Фамилия Имя»:
```javascript
function namesMatch(a, b) {
  // Сравнение множеств: нужно совпадение ВСЕХ частей меньшего имени
  partsA = new Set(a.split());
  partsB = new Set(b.split());
  matchCount = partsA.filter(p => partsB.has(p)).length;
  return matchCount >= Math.min(partsA.size, partsB.size);
}
```
Алиас: «Ольга Гайдукова» ↔ «Онлайн-оплаты» (в мотивации)

## 8. Как обновить данные

### Если обновилась таблица мотиваций (Google Sheets):
1. Скачать CSV с gid=334964199 в `data/motivations.json`
2. Перезапустить сервер: `kill $(lsof -t -i:3000) && cd ~/projects/web-interface && node server.js &`

### Если обновилась выгрузка B24 (deals_2026.json):
1. Запустить `python3 scripts/run_daily.py` в drop-dashboard
2. Или полный цикл: `python3 scripts/fetch_deals.py && python3 scripts/merge.py`
3. Пересчитать анализ: `python3 /tmp/compute_from_b24.py`
4. Перезапустить сервер

### Бекап:
```bash
cp -r projects/test-dashboard/data/ backup/$(date +%Y-%m-%d_%H-%M)/
```
